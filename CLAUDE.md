# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Read plan.md. It is the design record (format, data model, flows, decisions); README.md covers setup and usage.

## Git

Never commit or push unless the user asks in that message. Commit with the repo-local GitHub noreply identity (already configured here and in `../selfschool-courses`); the global email is private and GitHub rejects pushes that carry it. No personal data (names, emails, local paths) in files.

## Commands

pnpm workspace; Node >= 22. Dev runs in Docker, tests and the CLI run on the host.

```bash
docker compose up -d --build     # api (:3001) + web (:5174) in containers
docker compose restart api       # REQUIRED after changing API code: tsx watch misses bind-mount changes on Windows
pnpm test                        # all packages (vitest); pnpm typecheck; pnpm build
pnpm --filter @selfschool/api test                 # one package
pnpm --filter @selfschool/api exec vitest run test/catalog.lazy.test.ts   # one file (add -t "name" for one test)
pnpm --filter @selfschool/local dev                # the real web app + the real api running inside the browser tab, no Docker (:5175; add ?sample=1 on a first visit)
pnpm --filter @selfschool/web dev:mock             # web against a mock API (no Docker); preview config in .claude/launch.json
pnpm --filter @selfschool/api stress [-- --courses N | --live | --clean]  # 100-course load test, opt-in, self-cleaning
pnpm school validate <course folder>               # the format validator (needs `pnpm build` once)
```

Lint is Biome (`pnpm lint`, no formatter on purpose: no mass reformat). It exits non-zero only on errors; warnings are known debt (non-null `!` is allowed, `any`, a11y and hook-dependency findings are warnings), so do not add new ones in code you touch. `pnpm typecheck` must be clean before you hand work back. CI (`.github/workflows/ci.yml`, on every pull request) runs install, build, lint, typecheck and test in that order; `pnpm check` runs exactly that sequence locally and stops at the first failure, so run it before opening a PR. After editing `packages/shared`, run `pnpm --filter @selfschool/shared build`: the api and cli consume its `dist`, the web app reads its `src`.

## TypeScript conventions

- `tsconfig.base.json` is strict plus `noUncheckedIndexedAccess`, `verbatimModuleSyntax`, NodeNext. So: relative imports end in `.js` (also in tests), type-only imports use `import type`, and indexed access gives `T | undefined`.
- Validate at the boundary with zod and infer types from the schema (`z.infer`); do not hand-write a second type for something a schema in `packages/shared` already defines. Request/response shapes go in `shared/src/api.ts` so api and web cannot drift.
- Prefer `unknown` plus narrowing over `any`. Throw `HttpError` (api) for expected failures; never swallow errors silently.
- Ship small: keep changes scoped to the ask, no speculative abstractions or config. Run the touched package's tests and `pnpm typecheck`; run the full `pnpm test` before you say it is done.
- Tests live beside the code they cover (`test/` in api, shared, runner, cli; `*.test.ts(x)` next to the source in web). Add a test for new behaviour and for every bug you fix, and never loosen an existing assertion to get green.

## Architecture

- **Content in files, state in SQLite.** Courses are plain-file packages (`course.yaml`, `sources.md`, `NN-chapter/lesson-NN.md` + `quiz-NN.yaml`, `exams/`, `resources/`). Progress, attempts, the question bank and jobs live in SQLite (Drizzle, `packages/api/src/db`). They never mix. Courses are NOT in this repo: they live in the sibling repo `../selfschool-courses`, mounted into the api container at `/courses` (`COURSES_PATH`, `SELFSCHOOL_COURSES_DIR`). `examples/` holds fixtures used by tests.
- **`packages/shared`** is the contract: zod schemas for the course format (`course.ts`), every API request/response (`api.ts`), and the validator (`validate.ts`, run by `school validate`, on every package fetch and in tests). The authoring brief given to AI agents is generated from the same rules (`brief.ts`, `questionTypes.ts`). A new question type must be registered in `questionTypes.ts` (compile-time checked) and touches schema, validator, web input and grading.
- **`packages/api`** (Hono): `catalog.ts` scans the courses folder and is the performance-critical part. It keeps per-course entries with fingerprints, refreshes in the background (stale-while-revalidate, async walk, adaptive re-check), loads lesson bodies lazily (LRU), and persists a disk cache (`catalogCache.ts`). Summary endpoints read the light part (`course.light`) and `summaryCache.ts`; never touch `course.lessons`/`quizzes` on those paths. `ctx.ts` pins lesson revisions and loads authored questions into the bank when content changes. `packages.ts` imports courses (git clone, zip, local folder; multi-course repos return `choices`). `githubGit.ts` wraps the git runner: github.com URLs are fetched through the GitHub web APIs (commit sha, then the file tree, then each file pinned to that commit), anything else goes to the real `git`; it also backs `GET /packages/:id/updates` (`packageUpdates` in `packages.ts`: has the stored `ref` moved, which branches and tags exist), which the Settings package row calls on demand and feeds into the normal import popup to update or switch version.
- **`packages/runner`** runs on the host, not in Docker, because it shells out to the user's logged-in Claude CLI. It polls the api's job queue (chat, grading, question generation, verification). The app works without it ("AI is paused"). `packages/cli` is the `school` command (`up`, `down`, `doctor`, `new-id`, `validate`).
- **`packages/web`** (React 19, Vite, Tailwind, TanStack Query) talks to the api through typed `callApi` from the shared schemas. `VITE_MOCK` swaps in `src/api/mock` handlers. Layout follows `docs/ui.md`. Reader preferences (theme, font, content width, text size) are CSS variables set on `<html>` and stored in localStorage (`selfschool-*` keys), see `features/settings/prefs.ts`. Glossary terms in lessons become hover tooltips via a remark plugin (`features/lesson/glossary.ts`).
- **`skill/`** is the course-authoring skill (`SKILL.md` plus templates). Changing the course format means updating the shared validator, the templates, `SKILL.md` and `brief.ts` together.
- **`packages/local`** is the second way to run the app: the unchanged web app and the unchanged `packages/api` inside a browser tab (local-first, experimental). It runs next to the Docker setup, not instead of it: own port (5175), own Vite cache, own storage (IndexedDB), nothing shared with the containers, so both can run at once and do not share progress. It only adds shims, aliased over the api's Node imports in `vite.config.ts`: `better-sqlite3` -> sql.js (WebAssembly), `node:fs` -> a small in-memory filesystem, `node:crypto/path/url/util/child_process` -> browser versions, and the drizzle migrator -> bundled `.sql`. `fetch("/api/...")` and XHR are answered by `app.fetch` in the page; a service worker relays `<img>`/download requests to the page. State (SQLite file + course files) is saved to IndexedDB before each write's response returns (a save at tab close is not reliable). Its migrator writes drizzle's own `__drizzle_migrations` table, so database files are interchangeable with Docker's (backup restore both ways) and an old saved file is upgraded on start; never change an existing migration, only add new ones. `updates.ts` shows the "new version, reload" bar (compares the build id with `/version.json`, or reacts to `vite:preloadError`), and `VITE_LOCAL=1` (defined by its vite config) turns on the web app's backup reminder (`features/settings/backup.ts`). `pnpm --filter @selfschool/local test` also runs the whole api suite on the sql.js shim, so a new Node API in `packages/api` shows up there first. Rules for code in `packages/api` and `packages/shared`: keep Node-only calls to the set the shims cover (`node:fs`, `path`, `url`, `crypto` sha256/randomUUID, `util.promisify`, `child_process.execFile`, `better-sqlite3`'s `prepare/exec/pragma/transaction/serialize`), or add the missing shim; the 141-test run on sql.js in `packages/local` fails if the database layer drifts, and a new unshimmed Node import only shows up as a "externalized for browser compatibility" warning in `pnpm --filter @selfschool/local build` and as a runtime error in the browser, so check the page after touching these files. `SELFSCHOOL_BASE` sets its build's base path (GitHub Pages deploys it under `/selfschool/`, `.github/workflows/pages.yml`), so URLs that reach the network (service worker, `version.json`, router basename, `location.assign`) must use `import.meta.env.BASE_URL`, while `/api/...` stays root-absolute because the in-page transport and the service worker intercept it. The exception is a course-text link opened in a new tab: a navigation only reaches a worker whose scope covers it, so `TextLink` (web) points it at `<base>api/...`, which `sw.js` and `apiPath.ts` (local) also accept. Git URL imports work there because `githubGit.ts` in the api clones github.com repos through GitHub's web APIs (no git binary); no AI tutor in this mode yet.
- **Extensions** (extra chapters a user adds) go to `extensions/<course-id>/`, never into the package; the catalog merges them as level 2.

Windows host with a bind-mounted repo: file watching in the container is unreliable and file walks are slow, which is why the catalog polls and caches instead of watching.
